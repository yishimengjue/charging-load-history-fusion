# 公开实测负荷预测：TimeMixer对照结果

实验执行：2026-09-10；整理：2026-09-11。未覆盖此前ACN实验，未打开最终测试。

## 1. 本轮完成了什么

已在挪威住宅车库Bl2的**电表实测小时充电电量**上，完成季节基线、LightGBM和
小型TimeMixer的训练与验证。任务是午夜使用过去168小时，预测未来24个小时。
这不再是ACN恒功率会话代理曲线，但也不是15分钟功率或公共直流快充验证。

所有模型使用相同历史值、相同训练日和相同评分小时，不添加日历、天气、价格
或会话特征。TimeMixer使用固定版本官方代码、从零训练、原单位MAE损失、40轮
训练和三个固定种子。它是MAE适配的小配置对照，不是原论文完整benchmark复现。

## 2. 主要结果

以下为2019年9-10月**48个可评价日、1,152个小时**的验证成绩，越小越好。

| 方法 | 逐小时MAE / kWh | 由逐时预测求和的日总电量MAE / kWh |
|---|---:|---:|
| 前一天同小时复用 | 3.8562 | 38.4510 |
| 前一周同小时复用 | 4.1155 | 49.1396 |
| LightGBM | **2.9597** | 52.2886 |
| TimeMixer，种子42 | 3.2206 | 34.8174 |
| TimeMixer，种子43 | 3.3581 | 38.0001 |
| TimeMixer，种子44 | 3.2807 | 38.2638 |
| TimeMixer，三个种子的指标均值 | 3.2865 | **37.0271** |

TimeMixer最后一行是**每个种子先评分、再平均指标**，不是平均预测后的集成。
其逐小时MAE的种子间样本标准差为0.0689 kWh。

**以事先确定的逐小时MAE为准，LightGBM胜出。** 相比前一天/前一周基线，
误差分别下降约23.25%和28.08%；TimeMixer平均MAE比树模型高约11.04%。不能
因为TimeMixer更前沿，就把这次结果包装成深度模型精度提升。

但LightGBM存在更大的负偏差：-2.1399 kWh/小时，TimeMixer种子平均为
-0.2757 kWh/小时。TimeMixer的日总量误差更小，是有意义的业务指标权衡。
**逐小时P50之和通常不是日总电量的P50**；不能简单据此断言树模型“错了”，
也不能事后把主指标换成日总量来宣布TimeMixer胜出。偏态/稀疏分布与训练目标
可能有关，原因尚未由独立实验识别。

## 3. 稳定性与数据边界

以“第二种方法更好”为正，日MAE差的7日/14日分块95%区间为：

| 比较 | 7日块 / kWh | 14日块 / kWh |
|---|---|---|
| 前一天基线 → LightGBM | [0.5431, 1.2121] | [0.4924, 1.0387] |
| 前一周基线 → LightGBM | [0.5780, 1.5401] | [0.6254, 1.3898] |
| LightGBM → TimeMixer种子平均损失 | [-0.5208, -0.0230] | [-0.4627, 0.0208] |

树模型相对季节基线在本验证期有较一致的优势；TimeMixer未建立MAE优势，但
14日区间跨零，不能说两种分块都证明它显著更差。这里只涉及一个车库的
验证期时间不确定性，不是多站泛化或独立最终测试结论。

原验证期共有61天，统一完整168小时历史加24小时目标的规则保留48天：9月
30天和10月9日至26日的18天。10月1日两小时标签缺失，排除了10月1日至8日；
10月27日DST歧义/重复影响当日及之后的历史窗口，排除了10月27日至31日。
规则未按模型误差调整。结果不能代表被排除日期或连续全时段运行性能。

时间保持当地民用时间，没有猜测DST偏移。预测假设每小时电表值在区间结束
即刻可用，但原数据没有在线入库延迟记录，此假设不是已验证的生产条件。

## 4. 如何避免挑结果

- 两种可训练模型各两个配置，只有2019年7-8月的62天用于选择；选中
  LightGBM l0和TimeMixer t0后先保存选择文件及哈希，再执行9-10月验证。
- TimeMixer不选最好种子、不早停、不额外平滑；所有模型统一非负截断。
  模型按月从头训练，10月允许使用已结束的9月样本，不能偷用10月未来目标。
- 四次月度训练的日样本数分别148、179、210、240，架构之间逐次窗口指纹相同。
  数据和候选预算一致不代表计算量或有效模型容量完全相同。
- 最终测试2019年11月至2020年1月的2,208个小时目标仍屏蔽，未生成最终测试
  预测、未查看目标数值或其缺失率。本次运行没有解析原始CSV。

## 5. 研究下一步

保留LightGBM逐小时P50作为当前基线，保留TimeMixer负结果，不继续堆叠模型。
下一项更有针对性的假设是：**明确区分逐小时P50、均值和日总量预测目标，能否
在不牺牲原指标的前提下改善运营所需的总量/偏差？** 应先冻结新的损失/目标
对照方案，再用开发期和验证期探索，而不是对最终测试反复调参。

本轮没有验证ACN的到达记忆可迁移到实测数据，也没有训练TabPFN/Chronos。
这次推进的是公开实测基准和方法适用边界，不是已经形成顶刊创新或价格因果结论。

## 6. 验收与复现

隔离环境`.venv-ams`安装PyTorch 2.8.0，不改变原`.venv`。TimeMixer官方源码固定
commit `e24610583b36fdd8c76cc17a8df4e65759a5f460`，4个代码文件和LICENSE均核验
Git blob与SHA256，未经修改。选中t0有88,503个参数。

全套337项测试在新环境通过；原快照65个文件SHA256一致。独立验收通过11个
输入、18个实现、60个产物哈希和18项归档成员，重建24次拟合的共同窗口、
全部42行指标、27行种子汇总和6个分块区间，确认封存测试未揭露。

smoke_v1保留为早期验收；随后仅将含混的元数据字段从“未用验证期训练”改为
“未用验证集早停”，未改模型。当前源码重跑smoke_v2后执行full_v1，后两者
源码一致。完整运行记录用时约54秒，时间包含本地缓存/设备条件，不作通用性能承诺。
